Aureal A3D Hardware Emulation: Research & Implementation Log

Project: Recreating the Aureal Vortex 2 (AU8830) A3D 2.0 hardware experience on modern systems, including a full chip-level emulation path and a behavioral (WASM) fallback.

1. The Target: Aureal Vortex 2 (AU8830)

The AU8830 is a fixed-function PCI audio accelerator released in 1998. It is not a general-purpose CPU; it is a dedicated DSP. Its internal architecture is built around the Vortex Audio Dataflow Bus (VDB), which interconnects several processing blocks:

  • A3D Engine: Handles 16 simultaneous A3D sources, HRTF (Head-Related Transfer Function) filtering, atmospheric absorption, and up to 64 wall reflections (Wavetracing).
  • Wavetable Synthesizer: 320 voices (64 hardware, 256 software). When not used for MIDI, these channels can be repurposed for A3D reflection rendering.
  • Digital Mixers & Sample Rate Converters: 32-input, 16-channel mixing and 16-channel SRC.
  • 10-Band Equalizer: Hardware stereo graphic EQ (96dB SNR).
  • Crosstalk Canceller: A biquad crossover filter designed to optimize stereo speaker playback.
  • PCI Bus Controller: PCI v2.2 bus master with 96 DMA channels.
  • Legacy Emulator: Hardware Sound Blaster Pro / DOS compatibility.

Key Detail: The A3D engine does not calculate the geometry of the level. The game/CPU calculates the reflection paths and sends the resulting parameters (delays, attenuations) to the chip. The chip applies the HRTF and mixes the audio.

Reference: Aureal Vortex 2 (AU8830) Product Brief (The only public architecture document; it does not contain register maps).

2. The Codec: SigmaTel STAC9708

The Vortex 2 does not output analog audio directly. It connects to an AC'97 codec via a 5-wire AC-Link. A common codec paired with the Vortex 2 is the SigmaTel STAC9708.

To perfectly emulate the sound of the card (for the Null Test), you must also emulate the codec's behavior: its noise floor, its specific DAC/ADC characteristics, and the SS3D (Sigmatel Surround 3D) stereo enhancement feature. Fortunately, the STAC9708 is fully documented.

Reference: SigmaTel STAC9708/11 AC'97 Codec Datasheet (Full register map and AC-Link protocol provided).

3. Decompiling the Chip: The Reverse Engineering Process

The A3D engine's internal register map (the addresses and data values that control HRTF, reflection taps, and occlusion) was never publicly released. It must be reverse-engineered.

3.1 The Hardware Setup

You need a native Windows 98 SE machine with a real Vortex 2 card (e.g., Aureal SQ2500, Turtle Beach Montego II, or Diamond Monster Sound MX300). Modern systems with PCIe-to-PCI adapters will not work for driver tracing due to missing Win9x driver support.

3.2 The Tools

  • SoftICE: A Ring 0 kernel debugger. You set a breakpoint on the card's memory-mapped I/O (MMIO) region. When the driver writes to the card, SoftICE freezes the system.
  • Bus Hound: A PCI bus tracer that logs all data moving between the CPU and the card.

3.3 The Method

  1. Boot the Win98 machine and load the official Aureal driver.
  2. Launch an A3D 2.0 game (e.g., Thief Gold).
  3. Trigger a specific audio event (e.g., move behind a wall to trigger occlusion).
  4. The debugger catches the driver writing to a specific address. Record the Address and Data.
  5. Correlate the write with the game event. For example, if moving left causes a write of 0x00FF to address 0x27B04, you have found the left/right panning register.

Starting Point: The open-source Linux au88x0 driver (specifically au8830.h and au88x0_a3d.c) contains partial DMA and routing addresses. These were collected by reverse-engineering the old Windows asp4core.vxd file. Use these as your baseline.

4. The Null Test: Proving Emulation Accuracy

Once you have built your software emulator, you must prove it is accurate.

  1. Record the Real Hardware: Capture the audio output from the Win98 PC using a high-quality digital or analog capture.
  2. Record the Emulator: Capture the audio output from your emulator playing the exact same game event.
  3. Invert and Sum: Align the two audio files in an editor (e.g., Audacity). Invert the phase of one track and mix them together.
  4. The Result: If the emulation is perfect, the audio will cancel out into absolute silence. Any residual sound (hiss, delay, echo) is the error in your emulation.

5. Headphone Selection for Testing

To accurately verify the emulation, you must use plain stereo, neutral-sounding wired headphones. Do not use "7.1 Virtual Surround" gaming headsets, as their internal HRTF processing will double-process the audio and ruin your reference.

  • Reference Standard: Sennheiser HD 800 S. Widest soundstage, highly accurate, positionally invariant.
  • Practical Choice: Sennheiser HD 599 or HD 560S. Neutral, open-back, no DSP, comfortable for long sessions.
  • Positioning Specialist: Audio-Technica ATH-AD700X. Airy presentation, excellent for directional cues and footsteps.
  • Detailed Option: Beyerdynamic DT 990 PRO. Bright treble, reveals high-frequency errors (occlusion muffle, reflection sharpness).

Warning: Do not buy a headset with built-in DSP (e.g., SteelSeries Arctis, Razer BlackShark). They will mask the flaws in your emulation.

6. The Alternative: Behavioral Emulation (WASM Router)

If full chip-level emulation is too complex, the alternative is a "behavioral" emulation. This is a WebAssembly (WASM) audio router that intercepts the game's audio calls and performs the A3D logic on the CPU.

  • Mechanism: The game calls a generic audio API. The router casts rays against the game's level geometry, calculates occlusion and reflections, and feeds the results into modern OpenAL (EFX) filters.
  • Advantage: Runs on any modern browser or OS. Does not require the original hardware or drivers.
  • Disadvantage: It recreates the intent of A3D, not the exact hardware output. It will not pass the Null Test against the real card.
